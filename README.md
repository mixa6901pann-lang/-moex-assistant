# MOEX Assistant

Автоматизированный ассистент для анализа и торговли акциями Московской биржи (MOEX).

Проект находится в активной разработке: от идеи (май 2026) до веб-интерфейса, бумажной торговли, реальной интеграции с Тинькофф, песочницы и риск-менеджмента.

---

## Что умеет

- **Утренний скринер** — каждый день в 10:00 МСК обновляет свечи и считает технические индикаторы (RSI, MACD, ADX, Bollinger, SMA, объём) по whitelist.
- **Внутридневной мониторинг** — каждые 15 минут в основную сессию ищет резкие сигналы.
- **Вечернее торговое решение** — в 18:00 TradingAgent анализирует день и предлагает сделки.
- **Бумажная торговля** — виртуальный счёт, P&L, win rate, ATR-стопы, trailing stop.
- **Реальные ордера** — полуавтоматический или live-режим через Тинькофф Invest API (с песочницей по умолчанию).
- **Песочница Тинькофф** — тестирование на виртуальном брокерском счёте.
- **Новостной сентимент** — RSS-агрегатор + LLM-анализ по тикерам.
- **Геополитический риск** — GeoRiskAgent сканирует новости и закрывает всё при критическом риске.
- **Дневник предсказаний** — записывает рекомендации и проверяет точность через 1/3/7 дней.
- **Веб-интерфейс** — `/desktop` и `/` (mobile), отключён по умолчанию на сервере.
- **Уведомления** — Telegram и/или VKontakte (опционально).

## Быстрый старт

### 1. Клонируй и установи зависимости

```bash
cd moex-assistant
pip install -e ".[dev]"
```

Требуется Python 3.11+.

### 2. Настрой переменные окружения

```bash
cp .env.example .env
# отредактируй .env своими ключами
```

Ключевые настройки:

| Переменная | Назначение |
|---|---|
| `LLM_PROVIDER` | `anthropic`, `gemini`, `yandex`, `ollama` или `none` |
| `LLM_FALLBACK_ORDER` | Порядок fallback между провайдерами |
| `TINKOFF_TOKEN` | Токен Тинькофф Invest API |
| `PAPER_TRADING` | `true` — только виртуальные сделки |
| `SEMI_AUTO_TRADING` | `true` — робот предлагает, ты подтверждаешь |
| `AUTO_TRADING_ENABLED` | `true` — открывать позиции автоматически |
| `TINKOFF_SANDBOX` | `true` — использовать песочницу Тинькофф |
| `API_KEY` | Ключ для защиты write-эндпоинтов |
| `WEB_UI_ENABLED` | `false` по умолчанию на сервере |

### 3. Запусти локально

```bash
python main.py
```

Или только веб-сервер:

```bash
uvicorn api.mobile_api:app --host 127.0.0.1 --port 8080
```

Веб-интерфейс:
- Desktop: `http://localhost:8080/desktop`
- Mobile: `http://localhost:8080`

Health endpoint: `http://localhost:8080/health`

## Торговые режимы

| Режим | Что происходит |
|---|---|
| `paper` | Виртуальные сделки, реального счёта не касается |
| `semi_auto` | Робот создаёт предложения, исполняешь вручную через веб-UI |
| `live` | Робот выставляет ордера сам (требуется полный доступ Тинькофф) |

Безопасность по умолчанию: `PAPER_TRADING=true`, `TINKOFF_SANDBOX=true`.

## Риск-менеджмент

- Максимум 5 открытых позиций (`MAX_OPEN_POSITIONS`).
- Риск до 2% капитала на сделку (`MAX_POSITION_PCT`).
- Размер позиции от 0.5% до 5% капитала (`MIN/MAX_POSITION_SIZE_PCT`).
- Стоп-лосс 2×ATR (`STOP_LOSS_ATR_MULT`).
- Trailing stop 2.5×ATR (`TRAILING_STOP_ATR_MULT`).
- Ликвидность: фильтр по среднему дневному объёму (`MIN_AVG_VOLUME`).
- Комиссия + плата за перенос учитываются перед открытием сделки.
- GeoRisk ≥ 7 — аварийное закрытие всех позиций.
- Дни заседаний ЦБР — блокировка новых позиций и ужесточение защиты прибыли.

## Деплой на сервер

Подробная инструкция в [`DEPLOY.md`](DEPLOY.md).

Кратко:

1. Сервер Ubuntu 22.04, Python 3.11+.
2. `bash scripts/setup-server.sh` — установит зависимости, supervisor.
3. Создай `.env` из `.env.server` и заполни ключи.
4. `supervisorctl reread && supervisorctl update && supervisorctl start moex`.
5. Не открывай порт 8080 наружу. Используй Cloudflare Tunnel или nginx + HTTPS + Basic Auth.

## Безопасность

- `.env` и `.env.tinkoff` игнорируются git.
- Web UI отключён по умолчанию; write-эндпоинты защищены `API_KEY`.
- CodeAct отключён по умолчанию (`CODEACT_ENABLED=false`).
- Приложение биндится на `127.0.0.1:8080`, не светится в интернет.
- Подробный чеклист безопасности: [`docs/2026-06-21—security-hardening-checklist.md`](docs/2026-06-21—security-hardening-checklist.md).
