## 1. Общая идея

MOEX Assistant — это автоматизированный аналитик российского фондового рынка (Мосбиржа). Он:
- Собирает рыночные данные (свечи, индикаторы, новости)
- Анализирует их с помощью нейросетей (Claude Sonnet 4.6 через OpenRouter, или локальная Gemma3:4b)
- Принимает торговые решения в виртуальном (бумажном) портфеле
- Ведёт дневник предсказаний и считает точность
- Предупреждает о геополитических рисках

## 3. Поток данных за один день

### 3.1 Утро (10:00 МСК) — Утренний скринер
- Обновляет свечи для 33 тикеров из whitelist
- Считает технические индикаторы (RSI, MACD, ADX, Bollinger)
- Формирует рейтинг: кто сильнее/слабее рынка
- Сохраняет результаты в базу данных

**Whitelist (разрешённые тикеры):**
SBER, GAZP, LKOH, GMKN, NVTK, ROSN, TATN, YNDX, PLZL, MGNT, MTSS, VTBR, ALRS, CHMF, NLMK, POLY, OZON, FIVE, SNGS, MOEX, RUAL, AFKS, PIKK, IRAO, PHOR, VKCO, SOFL, ASTR, SNGSP, RTKM, RTKMP, AFLT, UGLD

### 3.2 День (10:00–18:45) — Внутридневный монитор
Каждые 15 минут проверяет топ-10 тикеров скринера на резкие сигналы:
- RSI < 30 (перепродан) или RSI > 70 (перекуплен)
- MACD пересечение (бычье/медвежье)
- Всплеск объёма (Volume Spike)
- Гэп вверх/вниз

Если сигнал сильный — пишет алерт на VK-стену (если VK включён).

### 3.3 Новости (каждые 15 мин, 07:00–23:00)
- RSS-агрегатор читает Finam, РБК, Коммерсант, Ведомости, Интерфакс
- Собирает новости за последние **4 часа** (раньше было 20 минут)
- Пропускает уже обработанные новости по хэшу из таблицы `rss_seen_hashes`
- LLM анализирует не один заголовок, а **пачку из 5 самых свежих новостей** по тикеру
- Учитывает **возраст новости** (`age_minutes`) и **вес** (`weight`):
  - до 1 часа — вес 100%
  - 1–6 часов — 75%
  - 6–24 часа — 50%
  - 24–72 часа — 25%
  - старше 72 часов — игнорируется
- Сохраняет сентимент в таблицу `sentiment` вместе с `news_hash`, `published_at`, `age_minutes`, `weight`
- Используется TradingAgent при принятии решений

### 3.3.1 Анализ точности новостного сентимента
После накопления данных можно оценить, влияет ли свежий сентимент на точность прогнозов:

```bash
python scripts/sentiment_prediction_correlation.py
```

Скрипт сопоставляет прогнозы из `predictions` с последним sentiment по тому же тикеру и считает:
- общую точность прогнозов
- точность при наличии / отсутствии свежих новостей
- точность, когда sentiment совпадает с направлением прогноза vs противоречит ему
- корреляцию по весу новости, возрасту и уверенности LLM
- топ тикеров по точности 7-дневного горизонта

### 3.4 Геополитика (каждые 30 мин)
GeoRiskAgent сканирует новости на ключевые слова:
- санкции, война, Иран, Тайвань, нефть, газ, СВО, террор

Выдаёт **оценку риска 0–10**:
- 0–3: низкий
- 4–6: умеренный
- 7–10: высокий (критический)

**При 7+** — TradingAgent закрывает ВСЕ открытые позиции и не открывает новые.

### 3.5 Вечер (18:00 МСК) — Торговое решение
**Главное событие дня.** TradingAgent (Claude Sonnet через OpenRouter) запускает ReAct-цикл:

#### Шаг ReAct-цикла:
1. **Наблюдение** — система передаёт агенту текущее состояние: портфель, цены, геориск
2. **Мышление** — агент решает, какие данные нужны
3. **Действие** — вызывает инструменты:
   - `get_price("SBER")` — цена и свечи
   - `get_indicator("SBER", "rsi")` — RSI, MACD, ADX и др.
   - `get_news("SBER")` — свежие новости
   - `get_georisk()` — геополитический риск
   - `search_web("SBER санкции")` — поиск по RSS-лентам
   - `execute_python("...")` — математические расчёты
4. **Повтор** — 1-5 итераций, пока агент не уверен
5. **Решение** — JSON с action (buy/sell/hold/wait), confidence, reasoning, price

**Пример решения:**
```json
{
  "action": "wait",
  "ticker": "SBER",
  "confidence": 95,
  "reasoning": "Свободные средства 0 ₽ — нет возможности открыть позицию. RSI нейтральный, тренд боковой.",
  "price": 320.37,
  "qty": 0
}
```

### 3.6 Вечер (19:00) — Отчёт
- Формирует вечерний обзор рынка
- Публикует на VK-стену (если включено)

### 3.7 Вечер (19:05) — Проверка точности
Система берёт все «ждущие» прогнозы и сравнивает с реальной ценой:
- Прогноз был «long» по цене 320 → сегодня 325 → **correct**
- Прогноз был «short» по цене 500 → сегодня 510 → **wrong**

Считает статистику:
- Win rate (процент угаданных)
- Средняя ошибка
- По горизонтам: 1 день / 3 дня / 7 дней

### 3.8 Вечер (19:06) — Проверка бумажных позиций
- Обновляет текущую цену для всех открытых позиций
- Закрывает позиции старше 7 дней по таймауту
- Считает нереализованный P&L

## 4. Бумажная торговля (виртуальный счёт)

- **Начальный капитал:** 50 000 ₽
- **Максимум позиций:** 5 одновременно
- **Стоп-лосс:** 2×ATR (средний истинный диапазон)
- **Размер позиции:** до 2% от капитала

### Как агент открывает позицию:
1. Получает решение `buy`/`long` от TradingAgent
2. Проверяет: есть ли свободные деньги, не превышен ли лимит позиций
3. Открывает виртуальную позицию по цене закрытия
4. Записывает в журнал: тикер, сторона, цена, дата, причина («agent»)

### Как закрывает:
- По решению агента `sell`/`short`/`hold` (если позиция открыта противоположная)
- По GeoRisk ≥ 7 (аварийное закрытие)
- По таймауту 7 дней
- По стоп-лоссу (если цена ушла на 2×ATR против позиции)

## 5. LLM-провайдеры и fallback

### Первичный: OpenRouter + Claude Sonnet 4.6
- **Почему:** умный, следует инструкциям, почти не галлюцинирует
- **Стоимость:** ~$0.002 за запрос
- **Температура:** 0.1 (почти детерминированный)

### Резервный: Ollama + Gemma3:4b (локально)
- **Почему:** бесплатно, работает без интернета
- **Где:** на сервере Timeweb (если RAM ≥ 2 GB) или на твоём ПК
- **Минусы:** чаще галлюцинирует, медленнее

### Fallback-логика:
```
Запрос → OpenRouter (Claude)
         ↓
    402 Payment Required / 429 Rate Limit
         ↓
    Автопереключение на Ollama (Gemma3:4b)
         ↓
    Лог: "Переключаюсь на Ollama"
         ↓
    Ты видишь в логах → пополняешь OpenRouter
         ↓
    Следующий запрос снова через Claude
```

## 6. CodeAct — математика от LLM

LLM может писать и выполнять Python-код для расчётов:
- Корреляция Пирсона между двумя акциями
- Скользящие средние, стандартное отклонение
- Кастомные индикаторы

**Пример:**
```python
import numpy as np
from scipy import stats
sber = [322.96, 320.0, 321.02, ...]
gazprom = [115.41, 113.49, ...]
corr, p_value = stats.pearsonr(sber, gazprom)
print(f"Корреляция: {corr:.4f}")
```

**Безопасность:** Код выполняется в песочнице — нельзя открывать файлы, выходить в сеть, вызывать `eval`/`exec`.

## 7. База данных (SQLite)

### Таблицы:
- `candles` — исторические свечи (OHLCV)
- `screener_results` — результаты утреннего скрининга
- `predictions` — прогнозы TradingAgent (с reasoning)
- `prediction_checks` — проверка точности (1д/3д/7д)
- `paper_positions` — бумажные позиции (открытые/закрытые)
- `sentiment` — сентимент новостей
- `georisk_scores` — геополитический риск
- `dividends` — дивидендный календарь

## 10. Безопасность и ограничения

1. **Whitelist** — агент не может анализировать тикеры вне списка
2. **GeoRisk стоп** — при 7+ закрывает всё и молчит
3. **Бумажная торговля** — никаких реальных денег, только виртуальный счёт
4. **CodeAct sandbox** — запрещены `open`, `eval`, `exec`, сетевые вызовы
5. **Макс 5 позиций** — защита от переконцентрации
6. **Стоп-лосс 2×ATR** — авто-выход, если цена уходит против позиции

## 11. Типичные проблемы

| Проблема | Решение |
|---|---|
| Анализ пустой (цена = —) | Проверить базу данных, добавить колонку `reasoning` если старая |
| OpenRouter 402 | Пополнить баланс или дождаться авто-fallback на Ollama |
| Ollama не отвечает | Проверить `ollama serve`, перезапустить |
| Новостей нет по тикеру | RSS-ленты не всегда содержат все тикеры, введи текст вручную |
| GeoRisk = None | Агент ещё не сканировал, подожди 30 мин |
